**2026-05-18** — Brief workspace initialized. Intent: Create. Source material: brainstorming session (`_bmad-output/brainstorming/brainstorming-session-2026-05-18-kook.md`) covering Role Playing, What If Scenarios, and SCAMPER. App renamed from Kook → Kooks during SCAMPER to reflect social nature.

**2026-05-18** — Success criteria defined: primary = wife uses it and checks in daily; big success = her friends adopt it. Not pitching beyond that crew.

**2026-05-18** — AI webcam analysis (SCAMPER-S1) deferred to v2+. V1 includes webcam link access only (one-tap to Bogue Inlet Pier cam, conditions-triggered surface).

**2026-05-18** — Friends' pain not deeply validated; assumed similar morning friction. Brief will note this as an assumption.

**2026-05-19** — Check-in model expanded: binary in/out → in/out + break selection + expected arrival time, fully editable. Supports multiple sessions per day (crew occasionally surfs twice; friends arrive at different times). Replaces current ETA texting behavior.

**2026-05-19** — Terminology: "beach" replaced with "break" throughout. Surf spots are breaks (beach break, reef break, point break) — not all are beaches.

**2026-05-19** — "Nothing after 10am" principle retired. Multi-session support means the app is live whenever a session is happening. Ephemerality now applies to conditions verdict only (resets daily), not to the app's utility window.

**2026-05-19** — Ephemerality dropped entirely. Conditions are always live, updating every 15–30 minutes. No daily reset concept.

**2026-05-19** — "Session" removed as a product concept. The model is simply: friends know where you'll be and when. No session object, no session start/end.

**2026-05-19** — UX model revised to break-centric layout: one screen per break, swipe to navigate. Conditions verdict + friend presence + check-in all live on the break screen together.

**2026-05-19** — Check-in auto-expiry: 2 hours after stated ETA. No manual cleanup required; no stale presence.

**2026-05-19** — 10-word rule scoped to the conditions verdict on each break screen (not the whole app). The break screen has more elements; the rule governs the verdict component only.

**2026-05-19** — Per-check-in notify picker removed. Friendship is mutual opt-in via invite link; once connected, both parties automatically see and are notified of each other's check-ins. No selection per check-in.

**2026-05-19** — V2 idea captured: geolocation-based "Arrived" status. Presence model would show: in/out → planned ETA → actually arrived. Deferred; PWA geolocation is feasible but adds privacy/permission complexity.

**2026-05-19** — Geographic constraint removed. Breaks are user-defined and can be added/removed anywhere at any time. No pre-loaded defaults required.

**2026-05-19** — Open question flagged: break identity model undecided. Options: universal pre-defined database, GPS-proximity deduplication, or invite-link-based (creator shares break link, friends join that object). PRD will need to resolve this.

**2026-05-19** — Finalize: editorial passes applied (structural + prose). Status set to final. Decision log reviewed — all meaningful decisions captured in brief or flagged as open questions. No addendum needed.
