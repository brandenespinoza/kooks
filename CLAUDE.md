# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Kooks — a surf-crew presence PWA (T3 Stack: Next.js 15 App Router, TypeScript strict, tRPC v11, Prisma + PostgreSQL, Tailwind v4, shadcn/ui). Crew members check in at a surf Break with an ETA; the crew sees it in real time. Conditions verdicts are generated by an LLM from SwellCloud data on a schedule. Auth is invite-link only — no email/password.

Scale is deliberately tiny (1 primary user + 2–3 crew), single self-hosted instance behind Nginx Proxy Manager. Architectural choices assume that (in-process EventEmitter for SSE fan-out, pg-boss on the same Postgres).

## Commands

```bash
npm run dev              # next dev --turbo
npm run typecheck        # tsc --noEmit — the ONLY static check configured
npm run build            # next build (runs env validation via next.config.js)
./start-database.sh      # local postgres container from DATABASE_URL in .env
npm run db:migrate:dev   # prisma migrate dev (creates migration + applies)
npm run db:generate      # prisma generate (also runs postinstall)
npm run db:seed          # seed primary user from SEED_INVITE_TOKEN (idempotent)
npm run db:studio        # prisma studio
docker compose up --build   # full app + db stack, mirrors production
```

There is no ESLint, Prettier, or test runner installed. Do not invent `npm run lint`/`npm test`. Verification for a change is `npm run typecheck` plus `npm run build` (use `SKIP_ENV_VALIDATION=1` when env vars are unavailable).

Env vars are validated at startup by `src/env.js` (T3 env, Zod). Adding a var means editing `src/env.js` (both `server` and `runtimeEnv`) **and** `.env.example`.

## Architecture

**Request path:** client components → tRPC hooks (`~/trpc/react`) → `/api/trpc/[trpc]/route.ts` → routers in `src/server/api/routers/` merged in `src/server/api/root.ts`. RSCs use the server caller in `~/trpc/server`. Context (`src/server/api/trpc.ts`) carries `{ db, user, session }`.

**Real-time presence:** tRPC mutations write to Postgres, then emit a `PresenceEvent` on the `globalThis`-backed EventEmitter singleton in `src/server/events.ts`. The SSE route `src/app/api/presence/stream/route.ts` (needs `export const dynamic = 'force-dynamic'`) listens and writes to open streams; clients respond by invalidating TanStack Query caches — SSE carries the signal, tRPC carries the data.

**Scheduled work:** pg-boss initialized once in `src/instrumentation.ts` (Next.js server-boot hook — not in a route or component), registering SwellCloud polling, LLM verdict generation, dawn-patrol/night-before push, and check-in expiry cleanup (every 5 min, deletes rows where `eta + 2h < now()` and emits `checkIn.removed`).

**Conditions cache:** no cache layer — verdict, raw JSON, and timestamp live in columns on the `Break` table, written by jobs, read by `conditionsRouter`.

**Auth:** `Session` row + `kooks-session` HttpOnly/SameSite=Strict cookie. `/join/[inviteToken]` creates `User` + `Session` + a mutual `CrewMember` pair. Sessions currently have no expiry (V1, tracked in deferred-work). `src/middleware.ts` runs on Edge Runtime and **cannot reach Prisma** — it does a cookie-presence check only; real session validation lives in `protectedProcedure`.

**Database:** the full 8-model schema exists as of migration `20260901005755_full_schema`. Do not add a migration unless a change genuinely alters the schema. `User.homeBreakId` is deliberately not a foreign key (it would create a `User`↔`Break` cycle), so `break.delete` must null it manually on affected users.

**Deploy:** push to `main` → GitHub Actions builds the Docker image → GHCR → SSH to VPS → `docker compose pull && up -d`. The container runs `prisma migrate deploy` before `server.js`, so every schema change must ship with a committed migration. The Dockerfile explicitly copies Prisma engine/client/schema into the standalone output — those `COPY` lines are load-bearing.

## Conventions (from `_bmad-output/planning-artifacts/architecture.md`)

- `protectedProcedure` for every procedure except invite-link/onboarding; call `assertCrewMember(ctx, breakId)` at the top of anything touching break-specific data (throws `FORBIDDEN`).
- Import `db` from `src/server/db.ts` and `emitter` from `src/server/events.ts` — never instantiate `PrismaClient`, `EventEmitter`, or `PgBoss` anywhere else.
- Emit SSE events only after a successful DB write, always shaped as the `PresenceEvent` type; event names are dotted camelCase (`checkIn.created`).
- tRPC procedures return data directly — no `{ success, data }` envelope. Dates cross the wire as ISO 8601 strings.
- Prisma: PascalCase models, camelCase fields, `@map("snake_case")` on every field and `@@map` on every model.
- Files: `PascalCase.tsx` for React components, `kebab-case.ts` for everything else. Routers are `camelCase` + `Router`; Zod schemas `camelCase` + `Schema`.
- Server state comes from TanStack Query — use `isPending`/`isLoading`, never a hand-rolled loading `useState`. No optimistic updates in V1.
- Errors: `TRPCError` with typed codes server-side; `onError` → Sonner toast client-side.
- Path alias is `~/*` → `src/*`.

**Styling:** Tailwind v4 (CSS-first, no `tailwind.config.ts`). The "Morning Light" palette is defined as CSS custom properties in `src/styles/globals.css` and registered in the `@theme inline` block, so every token is a real utility: `bg-bg`, `bg-surface`, `bg-action`, `text-action-fg`, `text-text-primary`, `text-text-secondary`, `text-present`, `text-stale`, `border-divider`. Opacity modifiers work (`bg-action/80`). Use tokens, never raw hex.

**Never write `bg-[--surface]` / `text-[--text-secondary]`.** Tailwind v4 dropped the bare-variable shorthand — it compiles to `background-color:--surface`, which is invalid CSS and silently dropped by the browser, so the style vanishes with no error. Arbitrary *values* are still fine (`max-w-[430px]`, `text-[28px]`, `tracking-[0.14em]`); only bare `--var` references are broken.

Mobile-only shell: `max-w-[430px] mx-auto`, `pt-safe`/`pb-safe` utilities for iOS insets, 48px minimum tap targets, WCAG 2.1 AA contrast.

## Planning artifacts and workflow

This project is driven by BMad workflows; the specs are the source of truth for unimplemented work:

- `_bmad-output/planning-artifacts/architecture.md` — full Prisma schema (8 models), directory layout, enforcement rules 1–13. Do not invent models or files outside this tree.
- `_bmad-output/planning-artifacts/epics.md` — 6 epics / 19 stories with acceptance criteria and the FR→file map.
- `_bmad-output/planning-artifacts/ux-design-specification.md` — component-level design spec.
- `_bmad-output/implementation-artifacts/sprint-plan.md` — **status index across all 19 stories, and the cross-cutting replan corrections. Read this first.** Individual story files carry their own `Status:`, but this file is what keeps them honest.
- `_bmad-output/implementation-artifacts/` — one file per story with `Status:`, tasks, and dev notes. Epic 1 (1.1–1.3) is done; **Story 2.1 is next** and has no story file yet — generate it with `bmad-create-story`.
- `_bmad-output/implementation-artifacts/deferred-work.md` — accepted V1 shortcuts. Check here before "fixing" something that looks wrong (hardcoded compose password, no session expiry, no sign-out, 1.18GB Docker image, `pino` not installed).

**Epic 1 is complete.** Auth works end to end: `src/server/auth/` (session helpers + real `assertCrewMember`), `crewRouter` (`joinViaInvite`, `me`), `src/middleware.ts`, the `/join/[inviteToken]` and `/join-required` routes, and `prisma/seed.ts`. `protectedProcedure` and the `{ db, user, session }` context exist in `src/server/api/trpc.ts`.

Still absent: `src/server/{jobs,push}/`, every router except `crew`, and `instrumentation.ts` is still a stub (pg-boss lands in Story 3.1). `src/app/page.tsx` is a placeholder that only proves the session resolves — Epic 2 replaces it with the Break swipe stack.

**`assertCrewMember(ctx, breakId)` is real, not a stub** — call it at the top of anything touching break-specific data (rule 2). It allows the Break's creator, anyone sharing a `CrewMember` row with the creator, and anyone who has the Break in their `UserSavedBreak`; throws `FORBIDDEN` otherwise.

**Cookies from tRPC:** mutations set cookies by appending to `ctx.resHeaders` (threaded in from the fetch adapter), never via `cookies().set()`. `resHeaders` is optional — the RSC caller has none.

Implementation has diverged from the architecture doc in a few places — the code wins: PWA uses `@serwist/next` (not `@ducanh2912/next-pwa`, and it is installed but not yet wired to anything), shadcn/ui runs the `base-nova` style on `@base-ui/react`, and `pino` is not installed (logging is `console` for now).

**Deploy is live.** `deploy.yml` fires on push to `main` (plus manual dispatch). It needs the `VPS_HOST`, `VPS_USER`, and `VPS_SSH_KEY` repository secrets.
